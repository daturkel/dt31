The algorithm


  
Backtracking

  
Each digit appears once in every row, column and 3×3 box. The solver fills one empty cell with a digit that is still allowed there, then solves the rest of the board the same way. When it reaches a cell where no digit is allowed, an earlier choice was wrong. It removes the most recent digit and tries the next one in that cell. When a cell runs out of digits, it goes back one more level.

  
solve():
    choose an empty cell              # none left: solved
    for each digit allowed in that cell:
        place it
        if solve(): return true
        remove it
    return false                      # the caller tries its next digit

  
A move is one digit placed or removed. The chart under the terminal plots how many cells are filled after each move. Every rise is a placement and every drop is a backtrack. On the easy puzzle it climbs straight to 81. On the hard puzzle it climbs and falls back thousands of times before one branch reaches the top.


  
Choosing the cell

  
A plain backtracker fills the first empty cell it finds. This one scans the whole board and fills the empty cell with the fewest allowed digits, a rule called minimum remaining values. A cell with one candidate is forced, so filling it involves no guess. A cell with no candidates shows that the current branch is dead before any more digits go in. Ties go to the first such cell in reading order, and the scan stops early when it finds a forced cell.

  
The choice of cell changes how much guessing the search does. The table counts the digits each rule places before the puzzle is solved, including digits that are later removed when the search backtracks. Everything else is the same in both columns, including trying digits in ascending order.

On the easy puzzle there is always a blank with exactly one option, so sudoku.dt never guesses and places one digit per blank. Reading order often lands on a blank with several options, guesses wrong and has to back out, so it places 4,208 digits. On the hard puzzle even the best blank usually has two or three options, so both rules guess, and picking the best blank cuts the work by less than 4×.


  
The dt31 program


  
Memory layout

  
dt31 memory is a flat array of integers, here 2,048 of them (--memory 2048). The program splits it into fixed regions:

The stack is separate from memory. It holds return addresses and the values solve saves before it recurses.


  
Candidates as bitmasks

  
Each row, column and box mask has bit d set when digit d is already there. Bit 0 goes unused, so digit d is just 1 << d (BSL 1, R.d, R.bit). ORing the cell's three masks gives the digits it can't use. XOR with 1022, which is bits 1 to 9, flips that into the digits it can. cell_info does this for the cell in R.i:

Placing a digit ORs its bit into the three masks (mark). Undoing it XORs the bit back out (unmark). XOR clears the bit here because the bit is known to be set.


  
Counting candidates with a table

  
A number's popcount (population count) is how many of its bits are 1. For a candidate mask, that's how many digits the cell can still take: 0b0010111010 has a popcount of 5, for digits 1, 3, 4, 5 and 7. dt31 has no instruction for counting bits, so the program builds a table of popcounts at startup. build_popcount fills it in order from 1 up. Each entry is popcount(m) = popcount(m >> 1) + (m & 1): the entry for m with its lowest bit dropped, plus that bit. The entry for m >> 1 is always filled in already, because it's smaller. The table has 1,024 entries rather than 512 because the masks use bits 1 to 9, so the largest is 1022.

  

  
After that, counting a cell's candidates is a single memory read, CP [1024 + R.m], R.t. The grid below is the table from the run above: addresses 1024 to 2047, 32 entries per row. Darker squares have more bits set. The mask of the cell the solver will fill next is outlined in blue. Recursion for backtracking

  
solve changes a single board in place and undoes each placement on the way back, so a recursive call only has to save the cell and digit it's trying. dt31 registers are global, so a nested CALL solve would overwrite them. solve pushes R.i and R.d before recursing and pops them after. Success comes back through R.solved, and once it is 1 every level returns straight up.

  


  
Drawing with escape codes

  
COUT 27 writes the escape character, which lets the program control the terminal with ANSI escape sequences. ESC[2J clears the screen, ESC[row;colH moves the cursor, ESC[36m switches to cyan and ESC[m resets. After each placement or undo, draw_cell redraws one cell and the counters. Cell (r, c) sits on line 2 + r + r/3, column 3 + 2(c + c/3). The divisions skip over the border lines. The most recent draw_cell output from the run above:

dt31 prints with Python's print() and doesn't flush, so a terminal shows these updates in bursts at each newline. PYTHONUNBUFFERED=1 makes every update show up immediately:

  
PYTHONUNBUFFERED=1 dt31 run --memory 2048 sudoku.dt < sudoku_hard.txt

  
On the hard puzzle the program executes 7,726,475 instructions, which took about 9 seconds in dt31 when measured for this page.
